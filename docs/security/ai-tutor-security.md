# AI tutor security and privacy

All AI routes require the existing authenticated session. Every mutation uses the same Origin and CSRF dependency as learning. Request bodies forbid extra identity/role/preview fields. All conversation operations filter ownership; other-owner IDs return 404. Raw message bodies are bounded to 32,000 bytes, accepted question text to 4,000 characters (or a smaller configured limit), model text to 12,000 characters and upstream generation responses to 100,000 bytes. Mutations use fail-closed Redis limits of 30 requests per minute per user and client address. Ollama HTTP pooling and a configurable 1–4 slot semaphore bound generation concurrency per backend process. With multiple workers, allocate one process/slot per available model capacity or add a distributed generation scheduler later.

Draft access is exactly the existing policy: development AND preview enabled AND admin. Production admins have no draft access. The browser cannot grant preview. Course/unit/lesson gates run before text is assembled and again after generation. Historical sources are checked for current permission and version before any conversation text or feedback is exposed. Revoked preview history becomes unavailable, including replay and source associations; it is retained in the database for restoration only under authorized policy. Recommendation reads similarly recheck linked lessons.

Sources are real lesson foreign keys. No exercise-answer table or saved exercise snapshot is retrieved for the model. Retrieval permits bounded narrative section types and linked linguistic records; human curriculum review is still required to keep narrative explanations educational and free of accidentally embedded assessment answer keys. Model input cannot elevate the session's privileges, change preferences or inspect another owner. LLM prompt adherence is a secondary defense, not a security guarantee.

Turn IDs are UUIDs unique by conversation and role. Acceptance, generation and success/failure are separate transactions; inference does not retain a database transaction. A database lease rejects concurrent submissions. Expiry plus a random fencing token makes interrupted work recoverable without a stale worker clearing a new lease. A repeated UUID with different content returns 409. Successful retries return the original stored assistant message. Archived conversations reject new turns.

Ollama access is server-side only. There is no public provider URL in frontend configuration. The optional Compose Ollama service has no published port and is on an internal AI network; no model is downloaded at startup. The verified Windows-host path uses Docker Desktop's `host.docker.internal`, with the host service/firewall constrained to trusted local/Docker traffic. That hostname is deployment-specific: Linux operators must explicitly configure a reachable private address or use the internal service. Changing a base URL is an operator action; no learner-controlled URLs reach the adapter. HTTP redirects, ambient proxy credentials and credential-bearing provider URLs are disabled.

The local deployment was tested against the Windows host's Ollama. A future remote Ollama URL would transmit conversation text to that operator; do not advertise universal server-only processing. Conversations persist until an operator applies an explicit retention/deletion policy. Archiving is not deletion. This milestone does not run automatic purges, user export or deletion jobs. Define retention duration, access policy, backup handling and a deletion contact before public deployment. The UI explains retention and configured-server processing and discourages sensitive personal data.

The application logs sanitized failure types, never full prompts, messages, provider response bodies or raw exceptions. AI HTTP responses have `Cache-Control: no-store`. Httpx request logs may include the operator-configured hostname but not conversation bodies. Request tracing infrastructure must independently avoid payload capture. Test servers with fake providers are under `backend/scripts`, require an explicit flag and a `fluentloop_m05_*` database, and are never part of normal startup.
