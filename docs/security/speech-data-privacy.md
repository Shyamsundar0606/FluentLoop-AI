# Speech data privacy and authorization

Microphone capture is opt-in per explicit Record action. The browser shows actual recording/paused/off state, supports cancellation and local playback, and stops tracks on stop/cancel/unmount. Audio is sent only after Submit. Use HTTPS outside loopback secure contexts. Automated browser tests use fake microphone hardware; a real physical microphone test remains a manual user action.

Raw microphone audio is not stored by default. It exists temporarily in the browser Blob, bounded HTTP/multipart handling, private worker memory and decoder buffers. The upload is closed after processing. An unchecked per-recording choice can enable private replay; only then is input audio written to backend-controlled storage. Generated tutor/reference audio is stored for replay. Both expire for access after at most 24 hours (or a smaller configured retention). Files are removed by a bounded cleanup task every minute; large backlogs, downtime or filesystem failures can delay physical removal, but expiry is enforced at playback. Orphan files from failed persistence are also swept after TTL. Archival/metadata persistence does not imply raw-audio retention forever.

Files live in separate main/preview private volumes, never the public frontend directory. Storage keys are generated internally, not taken from upload filenames. Playback is `GET /api/v1/speech/audio/{asset_id}` with the authenticated owner session, no-store and nosniff headers. `DELETE` uses the same owner check plus Origin/CSRF and is idempotent for previously deleted owned metadata. Deletion removes the file and marks its metadata, leaving saved transcript/practice history intact. Expired/missing/deleted audio is unavailable without fabricating a replacement asset.

Every session, history, transcript, audio and pronunciation-progress query enforces ownership. Existing AI conversation permissions are rechecked, including all historical sources. Targets/target-derived audio re-resolve the lesson hierarchy and version at start, after generation and on playback/history. Revoked preview or changed/withdrawn content is hidden without deleting the protected records. The required draft policy remains development + enabled flag + admin; production admins are denied. No client preview flag or user_id is accepted by the speech request schemas.

Transcripts remain untrusted learner input. The tutor receives the same bounded authorized curriculum/history and first-name hint as text tutoring, plus French speaking policy. Email, registration age band, passwords, cookies, session tokens and unrelated profile details are not added. Ollama and the speech service have no autonomous database/shell/filesystem tools. Models are pre-provisioned from fixed repositories; user URLs and filenames never become commands or model paths.

The deployed workers have no public ports and separate internal networks. Strong distinct service keys remain environment-only and are never exposed to the browser. The worker receives only audio or synthesis text and its service-authentication header, not browser authentication. Raw audio/text bodies and keys are not logged; the worker disables access logs. Health returns availability without model paths. Core API readiness does not depend on speech. If operators configure remote speech/Ollama locations, disclose those locations before public deployment; do not claim audio universally stays on the same server.

Transcripts, assessment-unavailable metadata and attempt counts remain until an operator's explicit account-data policy applies. No automatic transcript deletion or user export is introduced. Define public retention/deletion policies, storage/backup controls and age-appropriate consent before offering longer-lived voice retention publicly. Filenames are random, not anonymous: voices and transcripts can identify people. Registration age bands are neither forwarded to inference nor used to infer legal eligibility.
