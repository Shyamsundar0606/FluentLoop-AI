# Voice learning system — Milestone 06

Uncertain utterances can be explicitly reviewed through the existing text endpoint with `reviewed_turn_id`. The server checks that the source is an uncertain, nonempty turn owned by the learner in the same session. Confirmation creates a new `user_confirmed` turn; the original ASR result is immutable. Existing JSON metadata stores the source turn ID, original words, confirmed words and timestamp. The request checksum includes the source ID, so a retry cannot silently attach a different original. The UI displays both versions after refresh. No schema change is required, and legacy text-fallback turns remain readable without invented provenance.

Voice prompts replace the explanatory text-tutor CEFR style with a conversational French policy. A1 asks for familiar present-tense French, one or two short sentences and one question. The validator enforces at most 35 French words and one question, and blocks profile/system/retrieval explanations before storage or TTS. An optional short `English:` line follows the French and is excluded from speech. Text tutor policies remain unchanged. A rejected model response returns controlled unavailability; it is not silently rewritten into a canned reply.

Voice practice is an optional addition to the text tutor. FastAPI authenticates every speech request, validates ownership/publication permissions and delegates audio processing to a private worker. Existing login, curriculum, exercises and text tutoring never depend on the speech worker.

The four independent boundaries are container/decoded-audio validation, Faster-Whisper ASR, French Piper TTS, and pronunciation feedback. ASR/TTS have replaceable interfaces and a shared private HTTP adapter. `UnavailableAcousticAssessor` explicitly represents the absence of independently calibrated acoustic scoring. Word matching and ASR probabilities never become pronunciation percentages.

The browser requests microphone access only after Record French. MediaRecorder chooses WebM/Opus, Ogg/Opus or MP4 according to actual browser support. It supports record/pause/resume/stop/cancel and local review; capture tracks stop on stop, cancel and effect cleanup. A small safety margin stops recording at approximately 29 seconds, within the server's 30-second cap. There is no live streaming claim: completed recordings are uploaded as multipart bodies. WAV fixtures are also accepted.

FastAPI applies CSRF/Origin checks and 12 mutations per minute per authenticated user/client address. The request-body cap is the configured audio cap plus 16 KB multipart overhead; the audio itself is limited to 5,000,000 bytes by default. Filenames and declared media types are untrusted. Content sniffing recognizes permitted containers; PyAV independently decodes audio, rejects video/multiple audio streams, unsupported codecs, over-two-channel/96-kHz input, corrupt/non-finite samples and excessive duration, and converts to mono float32 at 16 kHz. Decoded samples are capped at 480,000. Decode-loop checks use an eight-second soft budget; the enclosing worker process provides the hard job timeout even if native decoding stalls.

The optional worker has separate single-job ASR and TTS slots. Each lazily starts a persistent child process and caches its model there. Concurrent work receives backpressure (503). A timed-out process is terminated and a later request creates a new one; requests are not retried indefinitely. The worker has a read-only filesystem, temporary scratch space, two CPUs, a 2-GB container memory limit and a PID cap. Linux children additionally limit virtual address space. This isolates inference from core API threads and database access. The worker has no database connection, shell/tool access, history or user profile. Readiness reports installed-file availability, not linguistic quality or guaranteed warm-model performance.

ASR detects language first. Confident non-French speech is not coerced into French. A non-French prediction below 0.8 confidence may produce an explicitly `uncertain`, French-constrained hypothesis, retaining the original language-detection metadata. Recording length does not convert a low-confidence prediction into definitive language evidence. Such hypotheses are displayed but never sent automatically to Ollama; learners can explicitly review/edit and submit them through text fallback. VAD with no voiced audio returns `no_speech` before interpreting language metadata. Silence/quiet, clipping, no-speech and uncertainty are distinct statuses; unusable input never receives a zero pronunciation score. A1–C2 tutor policies remain central in the existing tutor service. Voice requests add a short-French-turn instruction without changing the saved level or explanation preference. Names remain bounded first-name hints; age, email and credentials are not added to model context.

`speech_sessions` references the existing `ai_conversations`, rather than introducing another conversation system. `speech_turns` records upload/request identity, ASR metadata and existing assistant-message IDs. A turn accepts and commits a fenced expiring lease before ASR, commits usable transcription before AI generation, and releases transactions during every external inference call. Existing AI request IDs prevent duplicate AI turns after partial failures. A failed TTS call preserves the successful tutor text and returns audio unavailable; the separate audio-retry endpoint synthesizes saved French text without calling ASR or Ollama again. Only a bounded French portion (at most three sentence chunks and 600 characters, with a conservative language check) is synthesized; full tutor text stays available.

Pronunciation targets resolve real example/lesson associations through the publication hierarchy; reference notes come from permitted pronunciation records. The selected target is re-resolved after inference and on historical access. `pronunciation_attempts` and `speech_practice_progress` represent speech-specific activity rather than duplicating exercise grades. Recognition feedback compares normalized words; it cannot identify a specific sound error. Audio assets are private files with PostgreSQL ownership/expiry metadata. No raw blob is stored in PostgreSQL or Next.js public assets.

Session history uses bounded 100-turn pages; session and attempt lists use offset pagination. Model context remains bounded by the existing tutor memory policy. Archived AI conversations, version-changed sources and revoked preview permissions retain their records but deny protected reads, playback and reuse. The existing development + preview flag + admin rule is unchanged, including production-admin draft denial.

The initial scenario library reuses the 20 original M05 practice prompts, including introductions, boulangerie, directions, appointments, work/studies, interviews and advanced discussions. Their roles, vocabulary, grammar, outcomes and summary guidance remain authored practice prompts rather than claims of expert-reviewed course completion. New speech sessions use the saved level; choosing another level requires an explicit Settings change. Linking a historical conversation preserves its historical level.
