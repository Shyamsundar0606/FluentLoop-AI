# AI French Tutor — Milestone 05

The browser uses authenticated `/api/v1/ai` FastAPI routes. The backend owns retrieval, prompts, generation limits, validation and persistence. Ollama receives text only and has no database, filesystem, shell, URL-fetch or autonomous-action tools. Authentication, exercises and progress do not depend on Ollama readiness.

`backend/app/ai/providers/base.py` defines a synchronous injectable provider protocol with health and generation methods. `Generation` carries model identity and only provider-supplied usage. The Ollama adapter checks the exact installed model, uses a bounded HTTP pool and per-process semaphore, and never downloads, falls back or retries generation. Tests override the dependency in the test process; there is no production fake-provider setting.

Retrieval first filters the course → unit → lesson hierarchy through the existing publication policy. Current-level candidates are selected with escaped SQL text predicates over course/lesson text, vocabulary, grammar, objectives and dialogues. At most 24 candidates are expanded and ranked by normalized term counts, with a linked-lesson boost and stable ID tie-breaking; at most three 2,400-character source contexts reach the model. Linked word senses, examples, grammar rules/exceptions/examples, verb forms, objectives and dialogue turns have explicit limits. Only narrative lesson-section types are eligible. Exercise tables, grading snapshots, answers and options are excluded. Sources reference actual lesson foreign keys and content versions, with the lesson acting as the authorization and citation container for its linked records. No vectors or embeddings are required.

Search is lexical, not semantic. SQL lowercase behavior follows the database collation and does not guarantee accent-insensitive matching. Candidate expansion and substring predicates are bounded but can become expensive with a much larger corpus; measure relevance and query plans before adding full-text indexes or semantic search. There is no invented retrieval confidence score.

Five additive tables store conversations, messages, lesson sources, correction feedback and deterministic recommendations. Migration `20261102_0005` follows verified head `20261102_0004`. UUID ownership keys and indexes, timezone-aware timestamps, role/mode/level/status constraints and per-request uniqueness enforce the storage contract. Feedback ownership is derived server-side. All source references are real lesson foreign keys, avoiding polymorphic unvalidated references.

A conversation freezes the learner's existing level and mode when created. Changing preferences affects only new conversations. To practice at another level, explicitly change the saved selection and start a new conversation. There are exactly six levels, A1–C2; no automatic level changes or certification. Scenario selection must match the saved level. The versioned, original scenario library contains 20 independent practice situations, published as practice prompts and explicitly distinguished from expert-reviewed curriculum. It does not import draft course material or claim completed C1/C2 courses.

Memory includes at most 12 successful recent messages within an 8,000-character budget, current scenario, selected level and permitted source context. Full messages remain available in PostgreSQL with 100-message cursor pages and a 1,000-message conversation cap. No generated summaries are stored. Recommendations are currently separate deterministic activity views rather than extra model-prompt context. Two or more incorrect exercise attempts within an accessible lesson justify a lesson-topic review, based on the latest 200 incorrect attempts at that level. The service persists real attempt IDs, explains its rule and never names a specific grammar weakness without topic evidence. Otherwise it offers a neutral introductory suggestion. Refreshes serialize on the owner row and upsert the current recommendation set.

Acceptance commits a user turn and conversation generation lease before inference. The read transaction is released before the external call. A successful turn commits its assistant message, sources and optional validated correction together. Failure marks the user turn failed and clears only the worker's own lease. Replaying the same UUID and message returns the saved answer; changing text under the UUID returns 409. Concurrent conversation requests return 409. Leases expire after the configured request timeout plus 30 seconds, so interrupted work can be retried with the same UUID. Unique constraints and worker fencing prevent duplicate assistant turns. Browser retry IDs survive refresh in session storage. A disconnected browser may leave the synchronous worker running; reconnect retrieves the result or retries after lease expiry. There is no cross-process cancellation guarantee or streaming in this milestone.

Every history/read/replay/feedback/resume path rechecks ownership and all historical source permissions. Withdrawal, version changes or preview revocation conservatively hide the entire affected conversation rather than reusing protected memory. No old messages are deleted by revocation. Lists omit inaccessible conversations.

Responses use `general_knowledge`, `curriculum_context`, or `draft_preview` labels. Supplying real curriculum context does not establish that every generated statement is supported; the API deliberately avoids a blanket “curriculum verified” label. The UI renders citations supplied by the trusted application, never provider-created references. Model output containing URLs, source-ID patterns, numeric citations or internal policy markers is rejected. Schema validation is not linguistic certification; independent French review and broader model evaluations remain necessary.
