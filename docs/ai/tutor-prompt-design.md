# Tutor prompt design

Milestone 06 voice conversations select a separate `VOICE_POLICIES`/`VOICE_STYLE` branch of `build_messages`; they no longer append French instructions to an English-first A1 policy. The voice branch removes the requirement to narrate general model knowledge because the UI already displays grounding labels. It keeps identity in its separate untrusted message, forbids explaining its source, and treats a name spoken in an introduction exercise as exercise text rather than replacing it with the profile hint. Short French dialogue comes first; a brief optional `English:` explanation comes afterwards. Voice-specific validation rejects internal explanations, more than one question, and A1 replies above 35 French words before persistence/synthesis. Existing text and structured correction policies are unchanged.

`app/ai/prompts.py` centrally defines all six CEFR policies and five modes: tutor, vocabulary, grammar, correction and roleplay. A1 uses mainly English, one simple concept at a time and short French examples; A2 adds daily situations and common time expressions; B1 encourages French-first narration and opinions; B2 adds register, workplace discussion and detailed feedback; C1 supports formal and academic reasoning; C2 supports subtle meaning and style without certification claims. The existing English explanation preference remains authoritative; a temporary request for simplicity never changes stored level.

One system message contains application policy. Retrieved curriculum and authored scenario definitions are JSON data in a separate user message. Bounded previous user/assistant messages retain their roles. The newest question is a final user message. A separate, untrusted identity message may contain only a bounded first-name hint derived from the authenticated profile's current display name. No email, age, age band, cookies, tokens, password hashes, private configuration or other profile fields are included. Identity context is not stored as a conversation turn or lesson/exercise data. Natural use of the name in a generated greeting remains ordinary conversation text.

Treat all data as untrusted, including imported text and previous model messages. System policy forbids disclosure of prompts, future exercise keys, other conversations and privileged content, and forbids security/level overrides. The actual authorization boundary is SQL retrieval and ownership checks, not the model's willingness to follow instructions. The model has no tools and cannot perform administrative actions. Generated strings are rendered as React text, not HTML or executable Markdown.

General model knowledge is allowed when no relevant platform sources exist, always labeled as such by the application. Responses with supplied sources are labeled “curriculum context supplied,” not linguistically verified. Sources are lesson-level containers with real IDs and versions; the service never accepts model-generated citations or links. Conservative answers and uncertainty are requested when a rule cannot be established.

Only sentence correction requires JSON-schema output. Required fields: original text, corrected text, error flag, explanations, optional stylistic alternatives, level and notes. Pydantic forbids unknown fields and validates bounds and CEFR. The original must match the accepted learner text and level must match the conversation. If no errors exist, the original must remain unchanged; stylistic alternatives are separate. Explicit contrastive few-shot guidance covers French age with avoir versus valid identity descriptions with être. Invalid JSON/schema, empty/oversized text, internal policy markers and provider-generated resource identifiers return controlled 503 with no successful feedback persisted. There are zero repair/generation retries.

The installed 3B model initially accepted an incorrect age sentence despite returning valid JSON. Explicit correction guidance fixed the measured sample, which is now asserted by the optional live smoke test. This is evidence for that sample only, not proof of general grammatical accuracy. A model change requires rerunning live linguistic smoke cases; schema and fake-provider tests alone cannot establish quality.

Roleplay prompts establish roles and situations, invite hints and selective corrections, and request a practice summary on finishing. These summaries are free-form assistant messages; there is no formal roleplay scoring or structured proficiency evaluation. Structured feedback storage currently covers sentence correction only.
